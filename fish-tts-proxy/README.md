# vnm-fish-tts-proxy（Fish Audio 本地代理）

## 为什么需要它

Fish Audio 的语音合成接口不支持浏览器直接跨域调用，浏览器会把请求拦下
（CORS 限制）。这个文件夹是一个很小的本地转发工具：跑在你自己电脑上，
专门负责把 VN 插件发来的 Fish Audio 请求转发出去，再把语音传回来。
全程不经过第三方服务器，也不依赖酒馆自己的登录/会话机制（这条路踩过坑，
详见下面"为什么不接进酒馆路由"）。

有两种运行方式，选一种就行：

## 方式一：手动运行（最简单，改代码不用重启酒馆）

1. 双击 `启动.bat`。
2. 弹出一个黑色命令行窗口，看到 `[vnm-fish-tts-proxy] 已启动，监听
   http://127.0.0.1:8765` 就说明成功了。
3. **这个窗口需要一直开着**，用 Fish Audio 语音的时候都需要它在后台运行。
4. 不想每次都手动开，可以把 `启动.bat` 的快捷方式放进 Windows 的"启动"
   文件夹（Win+R 输入 `shell:startup` 回车能打开），这样开机会自动在
   后台跑起来，以后就不用管了。

## 方式二：作为酒馆插件自动启动（彻底不用管）

如果不想开机启动脚本、也不想手动双击，可以让它随酒馆一起自动启动：

1. 把这整个 `fish-tts-proxy` 文件夹复制到 `<酒馆安装目录>/plugins/` 下面。
2. 打开 `<酒馆安装目录>/config.yaml`，确认/加上一行 `enableServerPlugins: true`。
3. 完全重启酒馆（重启 Node 进程，不是刷新网页）。
4. 之后每次开酒馆，这个代理都会跟着自动启动，不需要再管它。

**这两种方式性能完全一样**——都是同一份转发代码、同一个端口
（默认 8765），只是"谁来启动这个进程"不一样。方式二里代理**没有**走
酒馆自己的请求路由，而是自己另开了一个独立端口，所以不会被酒馆的登录/
CSRF 机制卡住，也不会因为走了酒馆的处理链路而变慢。

## 为什么不直接接进酒馆自己的路由（`/proxy/` 或 `/api/plugins/...`）

试过接进酒馆自带的通用跨域代理 `/proxy/`，以及把转发逻辑做成挂在酒馆
路由上的服务端插件，两种都因为酒馆自身的登录会话/CSRF 机制在不同环境下
表现不一致而失败（请求被酒馆当成未登录直接拒绝）。所以最终方案是完全
独立于酒馆路由之外，自己开一个原始的 http 端口，绕开这整套机制。

## 自检

浏览器打开 `http://127.0.0.1:8765/status`，看到 `{"ok":true,...}` 就说明
代理已经在正常运行（不管是哪种方式启动的）。

## 换端口

默认端口 8765。方式一用环境变量 `PORT` 换端口；方式二用环境变量
`VNM_FISH_PROXY_PORT`。换了端口记得也去 VN 插件的设置页里把"本地代理
端口"改成一样的。
