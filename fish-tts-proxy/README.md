# vnm-fish-tts-proxy（Fish Audio 本地代理）

Fish Audio 的语音合成接口不支持浏览器直接跨域调用。这个小工具运行在酒馆所在的电脑上，把 VN 插件的请求转发给 Fish Audio，再把音频传回浏览器。

从 1.2.0 起，代理默认监听所有网络接口。同一局域网里的 iPhone/iPad 会自动使用当前酒馆页面的电脑地址，不再错误请求手机自己的 `127.0.0.1`。

## 推荐：作为酒馆服务端插件自动启动

1. 把整个 `fish-tts-proxy` 文件夹复制到 `<酒馆安装目录>/plugins/`。
2. 在酒馆的 `config.yaml` 中确认 `enableServerPlugins: true`。
3. 完全重启酒馆的 Node.js 进程。
4. Windows 防火墙首次询问时，允许 Node.js 访问“专用网络”。不要在公共网络上开放。

代理会独立监听 8765 端口，不需要另外运行 `启动.bat`。

## 备选：手动运行

双击 `启动.bat`，并保持弹出的命令行窗口开启。它与服务端插件使用同一套代理代码和同一个端口，因此两种方式任选其一即可。

## 电脑和手机自检

- 电脑浏览器打开 `http://127.0.0.1:8765/status`。
- 手机通过局域网访问酒馆时，再打开 `http://<电脑局域网IP>:8765/status`。

看到 `{"ok":true,"proxy":"vnm-fish-tts-proxy"}` 表示代理可访问。如果电脑成功而手机失败，通常是 Windows 防火墙未允许 Node.js 的专用网络访问，或路由器开启了客户端隔离。

VN 的 Fish Audio 设置中，“代理主机 / IP”默认留空即可：它会使用当前酒馆网页的主机名/IP。例如手机通过 `http://192.168.1.20:8000` 打开酒馆，TTS 会自动请求 `http://192.168.1.20:8765`。特殊网络环境才需要手动填写电脑 IP。

## 改端口或监听地址

- 手动模式：环境变量 `PORT` 和 `HOST`。
- 酒馆插件模式：环境变量 `VNM_FISH_PROXY_PORT` 和 `VNM_FISH_PROXY_HOST`。

默认端口为 `8765`，默认监听地址为 `0.0.0.0`。如果修改端口，也要在 VN 的 Fish Audio 设置中同步修改。

若酒馆页面通过 HTTPS 打开，浏览器可能阻止访问 HTTP 代理（混合内容）。局域网直连酒馆通常使用 HTTP；HTTPS 部署需要为代理配置 HTTPS 反向代理。
